# v0.24.1: DMR receive levels, synthesizer lock, FM levels

Digital channels receive at the level the baseband's demodulator is
calibrated at, one volume step above the FM one. The baseband's DC
offset follows the channel's frequency between the calibration points
instead of the value for the bottom of its range. While receiving, the
radio checks every 100 ms that the transceiver's synthesizer is still
locked, and locks it again if not, with a warning in the log. A retune
within digital receive sends the baseband only the settings that
changed.

FM: the codeplug's FM mic level (1 to 5) sets the transmit gain; level 3
keeps the gain used so far. Channels with an alternative band setting
transmit with a little more voice deviation. Wide channels leave
registers 0x35 and 0x36 as they were.

## Steps

| # | Do | Expect |
| --- | --- | --- |
| 1 | Flash | "DeltaMM 0.24.1"; `fm: microphone level N of 5`, N the codeplug's FM mic level; no "synthesizer unlocked" warning while idle on a channel |
| 2 | A 2 m DMR repeater, a few minutes between calls | Bursts and calls decoded at least as before at the same place |
| 3 | A 70 cm DMR repeater, the same | As step 2 |
| 4 | FM mic level 3: `fm 44` on a DMR channel, then on an FM channel | `0AFA` on DMR, `09F9` on FM |
| 5 | A DMR call through each repeater, then an FM call | Heard and answered as before; no "synthesizer unlocked" warning after transmitting |
| 6 | Move between DMR channels on both bands for a minute, quickly at times | No "synthesizer unlocked" warning; no refused receive set-up; calls still heard after it |
| 7 | FM mic level 1, then 5 (codeplug write, restart); `fm 44` on an FM channel; an FM call each time | `07F9`, then `0CF9`; the voice clearly quieter at 1 and louder at 5 than at 3 |
| 8 | `fm 35` on a DMR channel, then on a wide FM channel, then on a narrow one | The wide channel reads the same as the DMR one (kept), the narrow one differently; the register reads back the chip's state, not the value written |
| 9 | Into a dummy load: `fm tx 433000`, `ptt 3000`, `fm 59` while it transmits; the same at 433.500 MHz | The upper ten bits 6 higher at 433.000 MHz than at 433.500 MHz |

## Write stall: watchdog stall record and paced block copies

Part of this release; run on 2026-11-01, before the steps above.

A watchdog left unfed for 1.5 s is recorded as a crash naming the task
that kept the CPU, with its pc and lr; the next start logs it. A codeplug
write from the PC pauses a tick every four pages while it copies a block,
so the task that feeds the watchdog keeps running during the write.

### Before you start

- A verified backup of the radio (`dmm-radio check-backup` matches it).
- The codeplug saved with a codeplug tool, to restore if needed.
- The log port open in a terminal, logging with PC times.

### Steps

| # | Do | Expect |
| --- | --- | --- |
| 1 | `hang` on the console | `watchdog no longer fed; expect a restart within about 3 s`; the radio starts again after about 1.5 s with `last reset: software` and `crash: watchdog stall in task <name>, detail 1500` and its pc and lr |
| 2 | `dmrconf read -y a.yaml` | Done in seconds |
| 3 | `dmrconf write -y a.yaml` | Every write answered, no `Timeout`; `programming: codeplug written from the PC: restarting`, and the radio starts again with `last reset: software` and no crash line |
| 4 | During step 3, watch the `uptime` lines | One every 10 s through the whole write, each at most a few tens of ms after the full second (`.304`) |
| 5 | `dmrconf read -y b.yaml` | b.yaml is what QDMR's own encode and decode give for a.yaml |
| 6 | `dmm-radio check-backup` | Calibration, radio information and system area still match the backup |

### Results

Run 2026-11-01 on a D878UVII PLUS, with the write stall branch, the settings store,
menu, home screen and microphone gain branches and the loader in one
image.

| # | Result |
| --- | --- |
| 1 | Pass: `crash: watchdog stall in task IDLE, detail 1500` with its pc and lr after the restart; the loader kept the image confirmed |
| 2 | Pass |
| 3 | Pass: the write completes in about 9 s with every write answered; the restart is a software reset, with no crash line |
| 4 | Pass: the uptime lines keep coming through the whole write |
| 5 | Pass: the read-back matches |
| 6 | Pass: identical to the backup |

### If a write still stalls

Note the `crash: watchdog stall` line: its task, pc and lr say what kept
the CPU (look the pc up in the image's map or with `addr2line`). Then
repeat steps 2-5 on these builds in turn, to find the first one that
stalls:

1. upstream main (e18632e)
2. the settings store branch
3. the menu branch
4. the home screen branch
5. the microphone gain branch

### Undo

Restore the saved codeplug with the codeplug tool, and flash the previous
image if needed.
